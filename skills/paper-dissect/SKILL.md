# 论文精读

负责对用户指定的单篇论文进行原文读取、方法剖析、实验核查、真实增量判断，并整理成一篇连续的中文精读报告。默认将报告保存为本地 Markdown 文件；只有当用户明确要求保存到云文档/知识库时，才额外执行云文档发布流程。

## 内置资源

- `assets/templates/paper_template.md`：单篇精读的写作模板。开始成文前必须读取实际内容，并按模板结构组织报告。
- `references/writing-style.md`：写作指南，包含节奏、图示、公式、审稿口径和文风清洁规则。开始成文前必须读取。
- `references/doc-rendering.md`：云文档保存渲染指南。只有在用户明确要求保存到云文档/知识库时读取，用于把按模板组织好的内容转换为适合云文档阅读的发布稿。
- `references/description.md`：可选用户画像。只有当文件非空或用户提供了明确个人/工作背景时，才用于审视论文对用户实际工作的价值。

## 输入

可接受以下任一单篇论文入口：

- 论文标题
- arXiv URL（abs / pdf / html）
- DOI
- 论文 PDF URL
- 本地 PDF 路径
- 用户提供的单篇论文元数据（如标题、作者、链接、发表信息、摘要、PDF 路径等）

如果输入只有论文标题或 DOI，先定位可信的原文入口；无法可靠定位时向用户说明缺失项，不要凭标题臆测论文内容。

## 工作流

1. 获取原文入口：优先使用用户提供的明确链接或本地文件；如果只有标题/DOI，则先查找可信论文页面、arXiv 页面、出版方页面或 PDF。
2. 若论文存在可用 HTML 格式（如 arXiv HTML），优先按 DOM 结构化读取 HTML 页面内容：标题、摘要、章节、段落、图片/图注、表格/表注、数学节点、算法块和引用关系。不要只做纯文本粗抽。
   - 数学节点必须读取 `<math>` 的 TeX annotation（`annotation encoding="application/x-tex"`），缺失时再用 `alttext`，仍缺失则标记为 `[MATH_MISSING]` 而非猜测。
   - 表格需在保留数学节点后按行列结构抽取，避免数值、上下标和标准差丢失。
3. 当 HTML 不可用，或 HTML 虽可用但存在公式、表格、算法、图注、图片或关键数值缺口时，回退核对 PDF；若 PDF 仍无法可靠恢复结构化内容，再读取 TeX 源码或补充材料。不得在关键公式、实验数值或方法步骤缺失时凭上下文猜测。
4. 以“增量声明”为阅读视角贯穿全文：厘清前人边界、本文增量、内部机制、证据力度、适用边界与最终判断。
5. 读取 `assets/templates/paper_template.md` 和 `references/writing-style.md`，以模板作为最终报告结构组织内容，不要按阅读顺序写流水账。
6. 读取 `references/description.md`。若用户提供了个人研究方向、工作内容、产品场景等背景，在“总结与洞见”中结合该背景判断论文的实际启发；若未提供背景，则只基于论文主题和通用研究视角给出洞见。
7. 根据用户意图选择保存目标：
   - 如果用户明确要求保存到云文档/知识库 → 读取 `references/doc-rendering.md`，按照 Compose → Render → Publish：先按模板完成正文，再渲染成适合云文档阅读的发布稿，最后创建或更新文档；**不再额外写入本地文件**。
   - 否则 → 按「标题与文件名规则」保存为本地 Markdown 文件；

## 论文读取约定

- 不要同时把网页、PDF、源码/TEX 作为并行主入口读取；先确认主入口是否足够，再按需回退或核对。
- HTML 解析必须保留结构信息，尤其是标题层级、图表上下文、图片 `src`、公式语义和实验数字。
- PDF 读取时重点核对公式、表格、图注、实验设置、消融结果和局限讨论，避免只依据摘要或引言下结论。
- 关键材料（公式、实验数字、图表、实现细节等）缺失到无法支撑可信判断时，要明确指出缺失项及其对结论可靠性的影响，不要补想象。

## 标题与文件名规则

- 在完整阅读论文后再确定云文档名或本地文件名。
    - 云文档报告默认命名为 `{short_title} | {organization} | {publication}`。
    - 本地保存路径默认为 `/paper-dissect/{YYYYMMDD}-{safe_short_title}.md`：
        - `YYYYMMDD` 使用生成报告当天日期。
        - `safe_short_title` 将 `short_title` 转成短横线小写形式，去除非文件名安全字符。
        - 目录不存在时先创建。
- `short_title` 优先选方法名、模型名或最易检索的短标题；如果没有，就用原论文标题的精简版本。
- `organization` 根据作者身份或论文标识优先选读者最容易识别的主导机构、团队或公司名称（比如：Alibaba Tongyi、FDU & Shanghai AI Lab）。
- `publication` 优先使用会议或期刊简称加年份；如果当前只有 arXiv 版本，则写 `arXiv`。
- 缺失值优先补成可读占位，而不是内部 id：`organization` 不明时写 `Unknown Org`，`publication` 不明时写 `arXiv`。
- 不要把文件名、内部 token 或临时下载 id 放进标题里，除非用户明确要求。


## 返回结果

完成后以自然语言向用户简要说明以下信息：

- **保存位置**：本地 Markdown 文件路径 **或** 云文档链接（按本次实际选择的目标二选一）。
- **报告标题**。
- **关键材料缺失说明或可信度提醒**（如有，例如某项实验结果未在原文找到数字、某个公式仅在补充材料中等）。

## 约束

- 负责单篇论文的阅读、方法核对、实验核对、真实增量判断和精读报告成文。
- 不要把摘要直接粘成现成分析。
- 阅读过程中必要的中间信息可以以文件形式保存在 /tmp/ 下，报告完成后应及时清理。
- 论文标题、作者、venue、公式、实验数字、baseline、数据集、代码实现、论文贡献等必须来自可核查材料，不要虚构。
- 如果增量很薄，就直说薄；如果证据不足，就明确说明证据不足。
